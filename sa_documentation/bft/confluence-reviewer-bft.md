# [БФТ] CR-001 Сервис проверки системных требований аналитиков в Confluence (Confluence Reviewer)

## 1 Описание

Инициатива предусматривает разработку нового сервиса с web-интерфейсом (Confluence Reviewer) для контроля работы системных аналитиков в Confluence. Сервис ведёт реестр аналитиков, синхронизирует созданные ими Confluence-страницы и автоматически проверяет документы по двум факторам: соответствие заданному шаблону (скриптовая проверка структуры и заголовков) и качество наполнения (проверка содержимого средствами ИИ: полнота, непротиворечивость, понятность для потенциального разработчика). Руководитель получает отчёты с замечаниями в Markdown, возможность оставлять заметки и отправлять комментарии на исходные страницы Confluence напрямую из сервиса.

БФТ фиксирует, **что** должен получать бизнес; способ реализации (архитектура, модель данных, выбор интеграций) определяется на этапе системных требований (СТ).

| Видение UX | См. ниже |

**Видение UX:**

1. **Экран «Аналитики»** — список всех аналитиков команды; в карточке аналитика видны ФИО и email; отсюда же — действие создания карточки аналитика.
2. **Экран «Карточка аналитика»**:
   - список всех его Confluence-страниц, отсортированный по дате создания от новых к старым, с пагинацией при большом объёме;
   - поиск страницы по названию и по ссылке Confluence;
   - у каждой строки — статус проверки: «не проверено», «проверяется», «проверки пройдены», «проверки не пройдены», «ошибка»; статусы визуально различимы (цвет/иконка + текстовая подпись);
   - у каждой строки минимум два действия: web-ссылка для перехода на оригинальную страницу в Confluence и ссылка/кнопка перехода на страницу просмотра отчёта по данной странице;
   - кнопка ручного запуска парсинга всех страниц аналитика из Confluence (актуализация перечня).
3. **Экран «Просмотр документа / отчёт»**:
   - итоги валидации документа; если отчёта ещё нет — отображается соответствующая заглушка-текст (не пустой экран);
   - текст замечаний в формате Markdown с корректным рендером разметки;
   - отдельный блок заметок руководителя в Markdown с возможностью сохранения;
   - кнопка ручного запуска валидации документа;
   - действие «оставить комментарий в Confluence» с полем ввода своего текста — рядом с результатами проверки, чтобы обратная связь отправлялась без ухода из сервиса.

**Критерии приёмки (примеры):**

1. (ФТ-CR-1, ФТ-CR-3) После создания карточки аналитика с email X и запуска парсинга в списке появляются страницы Confluence, созданные пользователем X, в порядке убывания даты создания; каждая строка ведёт на оригинальную страницу.
2. (ФТ-CR-10) Документ, в котором отсутствует обязательный раздел шаблона, получает статус «проверки не пройдены» и замечание с указанием отсутствующего раздела/заголовка.
3. (ФТ-CR-11, ФТ-CR-16) Отчёт ИИ-валидации содержит замечания по каждому критерию (валидность, полнота, противоречивость, понятность) либо явное указание, что замечаний нет; текст отрендерен как Markdown.
4. (ФТ-CR-14, ФТ-CR-13) Если страница не редактировалась в Confluence позже последней валидации, автоматическая проверка её пропускает; ручной запуск валидации выполняется в любом случае.
5. (ФТ-CR-15) Во время проверки документ находится в статусе «проверяется», при техническом сбое — «ошибка», при успешном завершении — «проверки пройдены» либо «проверки не пройдены».
6. (ФТ-CR-16) Если отчёта по документу нет, на странице просмотра отображается заглушка (не пустой экран, не ошибка).
7. (ФТ-CR-17) После отправки комментария из сервиса текст появляется в комментариях исходной страницы Confluence.
8. (ФТ-CR-7) Список документов разбит на страницы (например, по 20 записей); сортировка от новых к старым сохраняется при пагинации и поиске.
